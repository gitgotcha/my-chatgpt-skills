# 源码追踪与教学注释

用户询问“实际如何实现”“代码如何保证”，要求文件/行号、代码讲解或学习注释时读取。

## 深度预算

局部源码问题默认只形成一个闭环：一张局部图、一个最多 5 个节点的源码索引、一个关键片段、一个失败或并发边界。最多 5 个节点只约束局部问题，不得拿它压缩用户要求的完整业务主链路；完整单元按[详细单元讲解格式](detailed-lesson-format.md)列出足以证明调用顺序的节点，必要时跨多轮讲。不要把“抢任务如何防并发”自行拆成多个新模块；相邻机制先作边界简述，等用户确认并继续后再展开。

## 追踪调用链

沿业务方向定位最短证据链：

```text
入口/路由 → 编排服务 → 领域或仓储操作 → 数据库/缓存/消息边界 → 回执或消费者 → 关键测试
```

搜索先从业务词、路由、表名、事件类型或状态值开始，再定位符号定义与调用者。不要因为类名相似就认定调用关系。

源码索引使用下表，只列回答当前问题所必需的节点。源码教学必须同时给代码围栏中的真实片段和独立索引；二者的文件、方法与行号相互对应。索引中的文件名使用本地核验过的可点击**绝对路径链接**并带起始行号；代码片段方便直接阅读，索引方便跳转核验。正文不再逐条重复同一批路径：

| 顺序 | 文件与行号 | 符号 | 输入/输出 | 状态变化 | 证明的结论 |
|---:|---|---|---|---|---|

文件链接必须经过本地核验；行号指向关键符号或语句的起始位置。没有本地文件时给仓库相对路径或明确说明无法核验，不能伪造绝对路径。摘要、伪代码和模拟实现不得伪装成摘录的真实源码。

## 分层解释代码

1. **方法契约**：谁调用、接收什么、返回什么、失败如何表达。
2. **核心路径**：挑选能回答问题的最小代码块，说明前置状态和执行后状态。
3. **保障机制**：事务边界、唯一约束、条件更新、版本检查、租约或重试分别保障什么。
4. **失败路径**：异常发生时哪些数据已经持久化、哪些尚未完成、下次从哪里恢复。
5. **测试证据**：测试覆盖了哪个不变量；只读过测试不能说“测试已通过”，实际运行后才能报告结果。

沿执行时序说明调用方、被调用方、关键输入/返回和状态变化；若请求线程、工作线程或异步消费者不同，明确谁执行以及先后关系。片段后的解释回答“这段代码在当前业务步骤做了什么、为什么需要、异常时影响哪里”，不要逐行翻译语法。

不要用方法名、注释或测试名称替代实现证据。讲原子性需要看到事务边界和失败行为；讲幂等需要看到稳定键、唯一约束或冲突处理；讲并发安全需要看到原子条件和提交保护。

## 教学注释

默认只在展示片段中加入并标注“教学注释”。注释应说明业务意图、数据语义、成立条件和失败影响，不逐行翻译语法。注释放在语句之前，禁止插入 SQL、字符串、模板或序列化内容中。

只有用户明确要求修改源码时才写入文件；先检查工作区，限定文件和注释范围，保留已有改动，修改后重新核验行号并运行相称测试。长篇讲解完成后，如用户要求先确认讲解，再停下来等待；确认后才出一道当前层级的问题。
