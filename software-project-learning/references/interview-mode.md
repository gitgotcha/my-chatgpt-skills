# 专业面试模式

专业面试模式复用主 Skill 的全部证据、时序图、案例、源码与优化规则，并在用户理解当前模块后增加面试训练。用户以 `project-12306` 指定项目时，映射到可读目录 `project/12306`，通过[RDS-JBryon 项目快照契约](rds-jbryon-runtime.md)读取共享快照；项目路由不唯一或工具不可用时，不猜项目，也不谎称读到了历史。

## 递进训练

1. 按[详细单元讲解格式](detailed-lesson-format.md)完成当前源码教学；用户要求确认后再追问时，先等待确认，不把讲解直接变成测验。
2. 确认后只给一道与当前模块直接相关的问题，不提前泄露答案。
3. 根据实际回答指出正确点、关键遗漏、术语或因果问题，并按本参考的评分规则给反馈。
4. 用户明确愿意继续训练后再给一个最相关的追问。用户能讲清主链路后，再逐步进入异常、并发、性能或设计取舍；不要首轮倾倒所有难题。
5. 仅在用户要求 STAR、项目表达或经历包装时进行 45—90 秒口述训练。

面试题可从原理、源码、设计/优化中选择当前最有价值的一类，不固定每轮三题。源码题必须依据实际代码；源码教学同时提供关键代码块和核验过的可点击绝对路径/起始行号索引。只有文档时只能问设计题或标注清楚的模拟实现题。高密度主链路可拆多轮；用户说今天到此为止时简短收束，不追加问题。

## 项目证据与复盘联动

- 正式项目题只在用户回答后追加到项目快照；保存 session、题目、原答、追问与补答时间线。次日框架回顾不是面试 attempt，不进入快照。
- 首答原文不可被修改；同题提示与补答作为后续 timeline 追加，评价独立记录。看过答案或接受提示需在反馈中说明，不包装成独立作答。
- 换人名、换数字、换项目显示名不构成新 `variantId`；改变故障模型、约束或时序条件才是新变式。专项复测必须新建 attempt 与 session，不能复用旧回答。
- 作答前不展示本题答案；最多提示一次，并标记 `assistance`。没有用户实际回答时停止等待，不构造 session、不产生评价。
- 评价只依据用户原答和当场证据；仅当用户要求保存评价或约定的面试流程包含结果复盘时，才把评价依据追加到同一个项目快照。单次分数不得自动变成长期掌握状态。

深度可按训练层次递进，不宣称公司内部标准或录用线：

| 层次 | 看什么 | 余票示例 |
|---|---|---|
| L1 链路 | 参与者与状态 | HGET 命中、`null`、字符串 `"0"` 分别怎么走 |
| L2 机制 | 为什么这样写 | 锁内二次检查防什么；局部 Map 与 Redis 谁负责返回 |
| L3 反例与修复 | 最小反例、修复、有区分度的测试 | A 回填、B 等锁后命中但空 Map，如何证伪并修复 |
| L4 迁移与取舍 | 换约束仍守契约 | 回填超时结果未知时怎样返回与观测 |

## 面试反馈

- 采用 100 分制：技术正确性 30、项目证据 25、因果与故障链 20、方案取舍 15、表达结构 10。问题未涉及的维度先说明并等比例折算，不凭空扣分。
- 评价必须引用用户实际回答，分别列出正确点、关键遗漏、错误或过度声明；不要因为没有复述标准答案原句而扣分。
- 标准答案先给直接结论，再给实现证据、成立条件和取舍。
- STAR 按 S（真实场景）、T（本人职责）、A（实际动作）、R（可验证结果）整理；不虚构用户参与、线上事故、用户量或性能指标。
- 用户切回普通项目学习时停止面试追问和 STAR，但保留已学模块与未解疑问。

追问遵循“主链路 → 失败路径 → 并发/幂等 → 优化取舍 → 个人贡献”递进。只有前一层回答已基本成立才进入下一层；缺少源码时不问无法由设计证明的实现细节，改问验证方案。
