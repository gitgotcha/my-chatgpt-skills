# 教学行为回归场景

供维护者使用，不是每次教学必读材料。对行为的验证应运行独立教学样本；文本关键词匹配不能证明教学有效。

## 运行与人工判定

- 每个样本使用新上下文，只有指定版本的技能、场景材料和用户问题。只读，不连接生产服务，不修改学习项目。
- 修改前先运行未加新指导的对照版本；同一输出形状场景每个版本至少 5 次。记录实际回答，逐条人工判断，不能只统计标题或字数。
- 设计规则不能混入学习者问题以提示答案。将下方“判定”留给评估者，不交给答题代理。
- 记录模型、版本提交、场景、失败原句及改进，不把小样本通过等同于真实用户长期学习效果。

## A1：项目学习模式的回答评判

材料：设计规定 `business_events` 保存不可变事实，`event_outbox` 保存待执行的画像更新任务；二者在同一事务中写入。只有设计，无源码。

前置对话：已经完成图表、案例和设计讲解。教练提问：“为什么事件和任务需要一起写入？”

用户回答：因为事件是事实，任务负责后续更新画像。如果只写事件没写任务，画像可能永远无法推进；同一事务可以避免这种半完成状态。不过这里只是设计要求，我还不能说源码已经实现了事务。

## M2：材料类型与模拟实现

分别以新情境运行：

- 只提供源码，询问实际业务如何运行。
- 只提供需求文档，要求用少量代码辅助理解。
- 同时提供规格与源码，二者对失败重试次数描述不一致。

判定：源码-only 场景标注业务意图推断；文档-only 场景将代码明确标为模拟实现且不编造路径；两者都有时指出差异，不擅自选择一方为真。

## I1：停止、歧义与模式切换

分别以新情境运行：

- 已讲事件、任务、Queue、增量画像。用户：接下来不用学了，这里停吧。

- 用户：现在切到项目面试，拿刚才的 Outbox 模块模拟问我一道题，我先答，你再点评。材料：设计规定事件和任务同事务保存，Queue 只传任务编号。

判定：停止场景简短收尾；歧义场景只问一次是否需要专业面试；进入面试时只问一道题并等待，不泄露答案；退出面试后保留当前模块并停止面试追问和 STAR。

## 单元二式输出验收清单

- 新模块先有一张流程图或职责/关系表；已有模块的追问复用原图，只补局部关系。
- 案例贯穿操作前、代码动作、操作后，解释不是把源码行逐句翻译。
- 实际源码讲解同时提供关键代码块和独立的可点击绝对路径/起始行号索引；二者均可单独用于阅读定位。
- 调用链按真实执行顺序排列，说明关键输入、返回、状态写入与责任服务；未核验的推断明确标注。
- 同步/异步、事务、Redis、远程服务等只解释当前链路必要的边界，不把“一个单元”扩成整套系统盘点。
- 一次只聚焦一个主问题；遵守用户要求的确认门槛和停止信号。内容已讲、用户确认、用户能独立解释是三种不同状态。
- 技术段严谨清楚；轻松语气只用于过渡和类比，不替代机制解释。
