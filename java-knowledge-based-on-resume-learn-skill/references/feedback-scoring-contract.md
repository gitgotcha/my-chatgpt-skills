# 反馈与评分契约

每道题回答后固定返回六个部分，并通过 `resume-knowledge.answer-scored` 事件提交，由 Worker 物化掌握度快照。

## 反馈六部分

1. **总分与四个维度分数**：先给总分，再给四维明细。
2. **已回答正确的内容**：明确列出答对的部分，不笼统夸赞。
3. **错误、遗漏和表达问题**：分条说明技术事实错误、关键点遗漏、回答链断裂与表达问题。
4. **推荐回答链**：给出该题应走的回答路径。
5. **参考回答**：给出面试可直接使用的完整表述。
6. **掌握度变化与保存状态**：说明本次得分、掌握度变化，以及事件是已进入 D1 Outbox 还是仍在 SQLite 排队；不声称 Drive 已完成。

## 评分维度

采用 100 分制：

| 维度 | 权重 |
| --- | --- |
| 技术正确性 | 40 |
| 关键点完整性 | 25 |
| 回答链路与层次 | 20 |
| 简历场景结合度 | 15 |

四维分数必须分别落在各自权重范围内，且加总等于总分。任一维度超出范围或总分与明细不符时，Worker 会拒绝该事件，技能应在提交前自检。

## 回答链

回答链按题型自适应：

- **场景题**：业务场景 -> 核心问题 -> 原理 -> 方案 -> 实现细节 -> 风险与替代方案。
- **原理题**：定义 -> 核心机制 -> 关键流程 -> 示例 -> 边界与常见误区。

以分布式锁为例：并发场景 -> 竞态、超卖或重复执行 -> 单机锁无法覆盖多实例 -> Redis SET key value NX EX -> 唯一 value 标识锁持有者 -> Lua 脚本原子校验并释放 -> 过期、续期与锁失效 -> Redisson 看门狗、主从一致性与 fencing token。

## 问题归类

回答问题的归类至少覆盖：技术事实错误、关键点遗漏、回答链断裂、项目场景结合不足、把推测说成实际经历、表达冗余或缺少结论。

## 展示边界

用户作答前，不得展示评分点、参考回答与推荐回答链。每日题单同样只返回题面，不携带答案内容。

## Outbox 回执

`submit_event` 返回 `deliveryState: "cloud_accepted"` 时，说明 SQLite 已落盘且 D1 Outbox 已接收；返回 `pending` 时，说明事件仍在 SQLite 持久排队等待自动重试。两者都继续给出完整反馈，但都不得称 Drive 或画像快照已经完成，也不得由 Skill 手工重发。
