# 专业路由与交接

本 Skill 只安排总量、窗口、顺序和停止边界。专业内容必须交给用户已有的专业 Skill；计划里列出某个 Skill，不等于已经运行它。

## 1. 路由表

| Skill 沉淀或创建 | `profile-aware-skill-creator`，基础层用 `skill-creator` | 分清收集素材、设计、实施、验证阶段 | 创建流程、目标路径、是否画像化、包校验 |

专业 Skill 在当前环境不存在、未安装或版本不明时，如实说明，不冒充已经运行，也不用规划 Skill 编造专业内容。

## 2. 交接卡

每个窗口给一张卡，字段固定：

```text
日期与任务键：
专业 Skill：
模式：
窗口分钟：
目标产出：
已知材料或入口：
明确未知项：
停止条件：
可返回的证据：
```

示例：

```text
日期与任务键：2026-10-20 / 12306-mainline
专业 Skill：software-project-learning
模式：项目学习模式（不是专业面试）
窗口分钟：120
目标产出：一条业务链的复述 + 一个明确卡点或检查结果
已知材料或入口：用户当前项目的实际仓库与上次保留的入口
明确未知项：当前掌握程度、上次停在哪、项目版本是否变化
停止条件：到点或用户说停止；不追加新模块
可返回的证据：用户实际复述、回答、尝试或卡点；不讲过即掌握
```

规划 Skill 只写这张卡和总量。专业讲解、源码位置、题目、评分、复盘报告由对应 Skill 产出。

## 3. 兼容点

### 3.1 简历八股仍是 V1

`java-knowledge-based-on-resume-learn-skill` 当前保留 V1 流程和 V1 回执语义。规划 Skill 采用 V2：

- 不顺手迁移旧 Skill；
- 不替旧 Skill 伪造 V2 回执；
- 没有简历时不能借它出“通用八股”；
- 可以保留学习窗口，请用户提供简历，或明确改成普通答疑。

### 3.2 算法每日协议有默认值

`algorithm-learning` 的每日协议默认 3–5 题并做近期去重。“一道新题、两道旧题”只是本会话的建议，用户尚未确认。规划 Skill 不把它写成既定偏好：

- 用户要三题：三题是目标数量，不是保证完成；
- 用户选择旧题复习：作为专项复习请求交接，不冒充默认每日新题流程；
- 专业 Skill 已记录算法事件时，规划 Skill 不重复提交。

### 3.3 真实面试的画像变化要专业确认

`reviewing-java-backend-interviews` 对真实面试的画像变化有单独确认规则。总规划授权不代替该确认。规划 Skill 只安排复盘窗口，不替它应用画像变化。

### 3.4 没有原始面试记录

没有真实面试会话时，可以做表达复练，但必须标注“练习”；不虚构真实面试，也不把练习写成面试复盘。

### 3.5 不重复专业事件

本 Skill 只写 `planning-execution` 证据，不重复写入算法、面试、项目等专业快照内容。不用另一领域的分数推导“执行力分数”。

## 4. 对话边界

- 同一对话由 Codex 选择并读取对应专业 Skill。
- 需要另开对话时，只提供可复制的交接卡，由用户自己打开。
- 本 Skill 不创建对话、不发送跨对话消息、不创建提醒或定时任务。
- 用户只要求列计划时，不开始讲课；用户说“开始今天的 12306”时才进入对应专业流程。

## 5. 环境核对

交接前确认专业 Skill 在当前运行环境确实可见。仓库里存在某个目录，不等于 Codex 已安装或已加载该版本。名称相近但内容不同的 Skill（例如项目学习 Skill 的旧名称与新名称）要先核对内容，不假定等价。无法确认时降级为普通答疑或只保留规划窗口，并说明未调用专业 Skill。
