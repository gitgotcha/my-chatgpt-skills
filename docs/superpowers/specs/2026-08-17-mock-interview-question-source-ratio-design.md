# 模拟面试题源比例设计

## 目标

让 Java 后端模拟面试更贴近真实面试：以简历和项目深挖为主，基础知识尽量绑定业务场景，同时保留历史弱点复测和算法/系统场景题。

## 题源配额

有简历或项目材料时，题目主来源采用互斥配额：

| 主来源 | 比例 |
| --- | ---: |
| 简历/项目 | 55% |
| 历史弱点变式 | 15% |
| 独立领域知识 | 10% |
| 算法与场景 | 20% |

主来源总和必须为 100%。领域知识和八股可以嵌入项目题或场景题，但通过 `topicTags` 标记，不重复计入主来源配额。

## 运行规则

- 题目数量不是 20 的倍数时，按最大余数法取整，优先保证项目题和算法/场景题的覆盖。
- 历史弱点变式不得复用原题；弱点复测不超过整场题数的 40%。
- 项目题可同时检查技术原理、架构取舍、故障处理和业务结果。
- 独立领域知识题只在无法自然嵌入项目或场景时使用。
- 无简历时继续使用无简历配额：历史弱点变式 35%、领域知识 45%、算法与场景 20%。

## 简历驱动出题

- 生成题目前先分析简历/项目材料，提取项目、职责、技术栈、指标、架构决策、故障案例和视觉重点区域，形成可引用的 `resumeClaimIds`。
- 项目题必须绑定具体简历声明；不使用脱离上下文的宽泛题目。每题聚焦一个核心能力，并标注 `sourceTags` 与 `topicTags`。
- 简历中的八股和领域知识必须优先放回对应项目场景；只有简历没有自然覆盖的知识，才使用独立领域知识题。
- 加粗、下划线、明确重点、主导/负责/优化等职责描述、性能指标、架构图和具体技术结论优先出题。
- 追问根据原回答的缺口生成，最多 1--2 次，围绕数据、边界、指标、异常处理或取舍，不改写 `originalAnswer`。

## 验收标准

模拟面试 Skill 必须明确记录上述有简历比例、主来源互斥计数、标签重叠规则、取整/弱点上限和简历驱动出题规则，契约测试必须锁定这些文字规则。
