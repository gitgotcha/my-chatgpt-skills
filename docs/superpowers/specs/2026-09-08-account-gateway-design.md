## 1. 已确认需求与边界

为其他用户提供可安装的插件，支持自助注册、查找本机已绑定账户、绑定已有账户；所有个人画像读写经统一账户网关。同一会话确认一次身份，各技能复用；用户明确切换时重新绑定。

已批准的身份语义：每个账户一个服务端生成的 UUID，允许同名账户拥有不同 UUID。姓名不是密码，也不能用于接管已有账户。用户确认身份的交互只做一次，不代表取消服务端每请求鉴权。

本规格只设计功能，不授权本轮修改代码、数据库、凭据或部署。后续实施保持 RDS 单次 invocation 最多 50 子请求的业务硬限制，不通过提高配额解决问题。

非目标：密码或社交登录、公开用户目录、姓名找回、账户合并、画像迁移、管理他人画像、修改姓名、云端账户删除。凭据全部丢失且无已认证设备时，第一版不提供自动找回。

## 3. 方案选择

1. 仅靠 Skill 记住姓名：操作少，但无法保证跨会话隔离与权限，不采用。
2. 独立账户网关工具、统一业务入口、服务端凭据校验：采用。复用现有 RDS 投影、Outbox、队列和归档。
3. 完整第三方登录平台：第一版不采用；会增加超出当前需求的系统依赖。

网关是 My Chatgpt Skills 插件中的公共能力，不要求用户再安装独立产品。账户操作经 account_gateway；业务仍经 submit_event，二者使用同一受控运行时。新增账户操作不是学习事件，不进入学习 reducer 或 Drive 画像。

## 4. 身份与权限不变量

- userId 是唯一数据隔离键；姓名做 NFKC 与首尾空白处理，仅用于显示及本机筛选。
- 新注册始终创建新 UUID；同名不是重试条件。只有同一次注册意图才幂等返回原 UUID。
- 服务端从有效凭据派生 principal；拒绝请求身份与 principal 不一致的读写。
- 不返回全站用户列表、姓名是否存在或对应 UUID。查找仅限当前安装已合法绑定的账户。
- 设备凭据不进入模型上下文、MCP 参数或回包、日志、事件、Git、截图。
- 本机操作系统账户是本机凭据的安全边界；共享同一 OS 账户的人不在第一版强隔离承诺内。
- 每请求服务端鉴权继续执行并计入同一个 invocation 预算；不缓存“永久有效”的授权。

## 5. 会话绑定契约

### 5.1 会话不是进程

必须通过目标宿主集成实验证实会话隔离。不能假定一个 stdio 进程只服务一个聊天，也不能接受模型随意填写 threadId 作为可信会话证明。

运行时适配器应从宿主提供的可信上下文取得隔离键；若宿主没有此能力，只能在证明 MCP 连接为每会话独立时使用连接作用域。两者均不能证明时，停止发布该宿主的会话复用功能，不能退回全局 currentUser。实施计划的首个技术验证门必须提供实测证据，不以文档假设代替。

### 5.2 本机状态

会话记录包含 sessionScope、accountHandle、userId、credentialRef、bindingRevision、validatedAt 和状态。真实密钥在 OS 安全存储中，credentialRef 只在运行时使用；模型仅能看到姓名、UUID、绑定状态和非秘密的修订号。

状态为 unbound、bound、reauth_required。解除绑定或进程重启可丢弃会话状态，但不删除本机账户或 Outbox。已有凭据重新验证后可恢复绑定，避免再次注册。

首次选择账户需要用户意图；明确提出使用本人已有账户且候选唯一即可绑定，多候选要求选择。已 bound 时各技能无需重复询问、无需再次执行姓名查询。上下文摘要或模型记忆本身不能恢复认证状态。

### 5.3 切换与竞态

用户明确切换后验证目标凭据，再以 expectedBindingRevision 做原子替换；并发切换只有一个成功。失败保持原绑定并明确报告未切换，不静默回退或重新注册。

所有异步画像读取捕获开始时的 userId 与 bindingRevision，回包时再核对；切换后的旧回包不展示、不进入新账户缓存。缓存键至少含 userId、namespace、projectionName、revision；切换清除该会话旧画像引用。

## 6. 对外工具操作

下表为待实现接口，不是当前已存在工具。工具必须采用封闭参数校验，未知字段拒绝。

| account_gateway 操作 | 模型可传参数 | 返回与效果 |
| --- | --- | --- |
| current | 无 | 当前会话绑定状态、姓名、UUID、bindingRevision；不返回秘密 |
| find | 可选 displayName | 仅本机已绑定账户的 accountHandle、姓名、UUID；至多 20 条，游标分页 |
| register | displayName | 启动本机注册确认流程，持久化同一注册意图；完成后返回已绑定账户 |
| bind | accountHandle、expectedBindingRevision | 验证本机已有凭据并绑定；不存在时拒绝，不以姓名远程接管 |
| transfer.create | 无 | 启动已认证账户的安全配对界面；MCP 仅返回 pending/ready 状态 |
| transfer.redeem | 无 | 启动新设备安全输入界面；配对成功才新增本机账户并绑定 |
| switch | accountHandle、expectedBindingRevision | 用户明确授权的账户切换；语义与 bind 共用 |
| unbind | expectedBindingRevision | 解除本会话绑定；不撤销设备凭据、不清理云端数据 |

注册、配对、切换必须有明确用户授权。运行时本机确认界面把注册与账户操作同普通模型调用隔离；取消不产生新绑定。一般学习流程不弹出注册，先报告未绑定并说明可选操作。

submit_event 在网关启用模式下先取得可信会话绑定，再派生身份和凭据；没有绑定时拒绝个人数据操作。业务方提供 identity 时仅做一致性核对，不允许其选择凭据。原生 capabilities 可无个人画像读取，但不能泄漏账户信息。

## 7. 自助注册与幂等

注册界面只要求姓名和确认，不要求用户处理管理员 token。服务端关闭管理员初始化接口，不将管理员密钥分发给插件。

本机在发请求前生成 registrationRequestId、至少 256 bit 随机设备秘密，并安全持久化注册意图；网络重试沿用同一意图与秘密。服务端只保存设备秘密的哈希。

服务端原子写入账户、设备凭据与注册幂等记录。幂等键需绑定该设备秘密的证明与规范化请求内容；知道 requestId 或姓名不够重放成功。同一意图不同姓名返回冲突；并发同意图仅一个 UUID；不同意图同名创建不同 UUID。

响应丢失时本机用原秘密证明重试，恢复原 UUID，不重新签发新秘密。本机无法持久化秘密时不发送注册请求；云端成功、本机账户元数据提交失败时保留注册意图恢复，不假称注册失败并创建另一账户。

姓名长度为规范化后 1–80 个 Unicode 标量、UTF-8 不超过 320 字节，拒绝控制字符；请求体不超过 4 KiB。禁止在错误中报告另一个用户是否存在。

## 8. 新设备一次性绑定

仅已认证设备可以申请配对码。配对码至少 128 bit 随机熵，有效期 10 分钟，单次使用；不能使用短数字码代替。每次申请计入限流。

配对码通过用户可见、模型不可读取的本机安全界面显示和输入，不通过聊天粘贴，也不作为 MCP 工具参数。该界面不使用截图回传、明文剪贴板自动写入或 URL 查询参数携带秘密。公开只返回成功或稳定失败状态。

目标设备先安全持久化新设备秘密及 redemptionRequestId。兑换时原子完成配对码消费、目标设备凭据新增与兑换幂等记录。所有凭据独立，可单独撤销；不复制来源设备的长期密钥。

同一兑换意图、同一目标秘密在丢响应后可以恢复同一结果；换设备秘密或换请求不能再次兑换已消费码。并发兑换只有一个胜出。恢复窗口为成功兑换后 24 小时，必须证明目标设备秘密；此窗口只恢复结果，不重复消费或新增凭据。

未消费码过期即拒绝；成功记录保留至恢复窗口结束后有界清理。设备禁用或来源账户禁用时拒绝新兑换。密钥丢失时不得通过姓名绕过绑定。

## 9. 画像与 Outbox 归属

业务事件进入 Outbox 前冻结 userId、原事件三个 ID、内容哈希及稳定账户引用。延迟投递根据该账户引用选择同账户有效凭据，绝不使用“当前会话账户”的 token。

选择每 UUID 独立的 Outbox 与服务实例，路径由运行时以 UUID 安全派生，不接受用户文件路径。迁移已有 V2 本机队列时验证每行冻结 userId；不能确认归属的行停止迁移并报告，不删除。用户先前允许清理 V1 不等于允许删除新 V2 记录。

切换 A→B 后 A 的待投递行仍用 A 的凭据；A 无凭据则阻塞待恢复，不伪装成 B。撤销凭据不能无限快速重试。用户解绑会话不自动删除设备凭据或队列。

回执保持现有层级：本机 pending、D1 committed、projection projected、archive archived 分开报告。认证缓存不能绕过现有事件幂等、读隔离、分页一致性与归档预算。

## 10. 存储变更与接口范围

新增迁移，不改写已应用的 0006/0007。移除 rds2_users.name_key 唯一性并建立非唯一查找索引；若需重建表，必须真实 D1 验证外键、凭据关系与数据守恒。保留所有既有 UUID、名称、事件、投影和归档。

新增逻辑实体：registration_intents（请求幂等、秘密证明哈希、账户及规范化内容哈希）、pairing_tickets（码哈希、来源账户、过期与消费信息）、pairing_redemptions（目标证明哈希、兑换幂等及恢复窗口）。复用 rds2_credentials 管理设备秘密哈希。具体 SQL、索引和事务守卫在实施计划逐条冻结，禁止先写业务代码再补原子性。

新增云端路由拟为 POST /v2/accounts/register、/v2/accounts/pairings、/v2/accounts/pairings/redeem。不新增按姓名公开搜索路由。账户管理与学习事实入口分离，不占用业务 SyncEvent 类型。

旧管理员按姓名发凭据脚本必须在启用同名注册前停止作为开户入口；否则可能把新设备绑到同名他人。原 user.resolve 保持仅核对 current principal，不能扩展为全局查询。

## 11. 限流、预算与失败处理

每个账户路由使用一个 invocation 预算器；认证、限流存储、失败收尾全部计数。每入口验收上限 20 次，运行时总预算仍不超过 40，业务硬上限 50；不得拆重置预算器掩盖超限。绑定码清理每轮最多 20 行、独立有界后台调用。

公开注册默认每来源 IP 每小时 5 次新账户创建尝试；配对兑换每来源 IP 每 10 分钟 10 次尝试；配对创建每账户每小时 5 次。限制是第一版可配置默认值，不是抵抗所有分布式攻击的承诺。部署前必须验证平台限流实现及成本，限流设施不可用时公开账户变更 fail closed，不开启无限制注册。

所有读写先做请求体上限、形状和字段校验。错误只返回稳定 code，例如 unbound、credential_invalid、binding_changed、registration_conflict、pairing_invalid、rate_limited、secure_store_unavailable；过期/错误/已被他人消费的配对码统一 pairing_invalid，避免额外信息泄漏。

临时网络错误允许用户重试原意图；不换幂等键、不回退姓名注册。日志仅包含操作、稳定 code、时长、预算计数、随机关联号；不含姓名、密钥、配对码、SQL 参数或原始请求体。

## 12. 技能与插件发布

新增 account-gateway 技能，说明何时确认身份、注册/配对用户交互、复用/切换规则及错误处理。各业务技能只引用公共契约，不维护独立认证副本。

技能发布范围取 Git 源与本机插件源的并集：算法学习、后端项目学习、Java 模拟面试、面试复盘、简历知识学习、儿童摄影、画像技能生成器。保留原业务功能；不需要个人画像的普通操作不强制登录。画像技能生成器产出的新技能也遵守网关，不再生成 V1 注册流程。

在 my-chatgpt-skills 中建立可版本化插件清单、公共技能与便携启动配置；MCP 运行时在 my-chatgpt-mcp 维护，通过锁定版本的发行包安装，禁止启动时拉取浮动 main。第一版支持 Windows 桌面及 OS 安全存储；其他系统明确不支持安全绑定，不能明文降级。所有路径使用安装位置解析，不写开发者用户名。

插件重装后新会话加载新工具。发布记录注明技能 commit、运行时 commit、包哈希、协议版本与最低运行时版本。不把本机缓存或未提交目录当作 GitHub 交付。

## 14. 实施与上线阶段

1. 先验证宿主可信会话隔离、安全配对 UI、安装包路径与限流能力；任一不能满足即停在设计修订，不假称已支持。
2. 编写审核后的实施计划：冻结接口、SQL、预算账目和测试证据，再开发账户存储与注册/配对事务。
3. 实现本机安全存储、网关会话、按账户 Outbox 与并发切换。
4. 统一技能 Git 源、安装插件源及协议引用，完成便携发行。
5. 本地双绑定测试及隔离测试后暗部署；保留既有用户读写，公开注册默认关闭。
6. 使用隔离测试账户验证双设备完整链；不向乔炳源画像写入测试学习事实。
7. 通过验收后启用自助注册、发布插件、提交并推送两仓库，提供可复核版本与测试命令。

回退先关闭新注册及配对入口，保留已有有效凭据与业务队列。不执行恢复姓名唯一约束的逆迁移；同名账户一旦产生，旧按姓名初始化逻辑不得恢复。不得以撤回部署为由抹除新账户数据。

## 15. 文档自检与下一审核点

本规格区分了姓名与认证、交互复用与服务端鉴权、注册与绑定、会话与进程、业务事实与管理状态。现存源码与拟实现能力分别标注。具体实施文件与 SQL 由下一阶段计划交付，不把设计预算当实测结果。

用户审核重点：同名不同 UUID；查找仅本机账户；第一版 Windows；配对通过安全界面而非聊天；宿主会话隔离为发布阻断门。通过书面规格审核后再进入实施计划，当前不进入代码开发。
