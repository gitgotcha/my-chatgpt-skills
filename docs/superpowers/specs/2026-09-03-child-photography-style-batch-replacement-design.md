# 儿童摄影样本学习与批量创作 Skill 替换设计

## 目标

用一个新的 `child-photography-editing` Skill 完整替换仓库中的
`child-photoShop-skill`。新 Skill 的唯一主业务链是：

```text
读取开发者样本 → 学习可迁移风格 → 锁定人物真实性 → 规划单图编辑区域
→ 批量生成 → 逐图 QA → 批次一致性 QA → 交付或安全回退
```

它不是通用选片工具，也不是自由换脸或全图重绘工具。选片、去重和联系表
从主流程移除；只有在批处理前确有技术坏片时做最小可用性检查。

## 替换范围

1. 删除旧目录 `child-photoShop-skill/`，新增规范化目录
   `child-photography-editing/`，不保留并行入口。
2. 修改根 `AGENTS.md` 的儿童摄影路由，使“参考样本、开发者样本、批量修图、
   换背景、主题布景、儿童海报、人物不失真”等请求只路由到新 Skill。
3. 修改根 `README.md` 的 Skill 清单、架构图、说明和链接。
4. 更新仓库级契约测试，禁止旧目录或旧路由重新出现。
5. 更新本机 `my-chatgpt-skills` 插件源、插件界面元数据和缓存版本，重新安装，
   使新会话只暴露新 Skill。

其他算法、后端学习、面试和画像 Skill 不改变行为。

## 最高优先级与冲突规则

授权与儿童照片隐私是执行前提；在所有视觉编辑决策中，人物真实性拥有绝对最高
优先级。优先级从高到低为：

1. 人物身份、身体结构、年龄感、姿势、动作和原始表情。
2. 用户限定的编辑范围，例如仅背景、仅肤色或仅裁切。
3. 服装与原有主题物件保护。
4. 同一批次的风格一致性。
5. 背景、主题、道具、海报文字与装饰效果。

如果低优先级目标会影响高优先级目标，必须降低风格化、缩小编辑蒙版或放弃该
效果。不得为了“出图成功”牺牲人物真实性。

### 不可协商的人物锁定

禁止换脸，禁止改变五官、脸型、头型、眼型、眼距、鼻子、嘴型、耳朵、发际线、
发型、发量、身体比例、四肢比例、手脚结构、年龄感、姿势、动作和原始表情。
哭泣必须保留为哭泣。眼睛仅允许轻微提神，不放大、不改变方向。头发不能被修掉。
服装默认完全不改，除非用户另行明确提出，但即使用户提出也不能改变身体结构。

标准流程禁止全帧重生成。生成式能力只能作用于人物保护区域之外的背景、外围
主题元素和不遮挡人物的版式区域。

## 输入契约

一次任务包含：

- `developerReferences`：至少一张开发者提供的样本或已确认的 Style Profile。
- `sourceImages`：一张或多张待修改图片。
- `editIntent`：`background-only`、`skin-only`、`crop-only`、
  `theme-edit`、`poster-edit` 或 `batch-style-transfer`。
- `outputSpec`：默认 3:5、1200×2000；用户明确值优先。
- `textSpec`：可选文字、语言、字体气质和必须避让区域。
- `perImageOverrides`：可选的单图例外，不得覆盖人物硬约束。

没有参考样本时，纯局部请求（例如“只换绿色背景”）可以使用用户直接给出的明确
风格参数；真正的风格迁移任务缺少样本时必须停止并索取样本。待修改图片缺失时
不得假装已经处理。

## 风格学习机制

开发者样本只提供可迁移的视觉语言，不提供人物身份。学习器把样本拆为：

- 背景：主色、辅色、纯色/双色、渐变、空间层次与纹理。
- 光线：方向、软硬、亮度关系、阴影密度和高光气质。
- 色彩：白平衡、饱和度、对比度、黑位、肤色倾向。
- 元素：道具类别、贴纸、手绘涂鸦、玩偶、地图、花朵、音符等视觉词汇。
- 版式：留白方向、文字区、元素密度、主次层级和边缘安全区。
- 主题：暖棕西部、Little Explorers、奶油棚拍、彩色高饱和童趣海报、
  绿色背景涂鸦、蜡笔小新萌趣日常绘本等可复用配方。

输出的 Style Profile 必须区分“观测事实、推断值、用户覆盖值”，记录每个维度的
置信度。不得从参考儿童学习或迁移脸、身体、年龄、服装、姿势或表情。

## 编辑规划与姿势适配

先为每张图生成 Edit Plan，再调用编辑后端。Edit Plan 明确允许区域、保护区域、
裁切、安全文字区、姿势类型、表情类型、需要的背景/元素和禁用操作。

- 坐姿：道具优先落在身体两侧或前景边缘，不覆盖手脚。
- 躺姿：围绕身体外轮廓布置，保留头顶、手脚和呼吸空间。
- 站姿：维持脚底接触和身体比例，元素避开轮廓线。
- 哭泣：保留泪水、皱眉、张嘴等原始表达，不转笑脸。
- 留白不足：减少文字和装饰，不挤压或缩放人物来腾位置。

肤色仅作低强度调整：整体提亮约 3%–5%，减轻灰黄，面颊、鼻尖、耳廓、手脚只
增加轻微自然血色，形成白里透红但保留婴儿真实肌理，不磨成塑料皮肤。

## 批处理一致性

同一批次先冻结共享 Batch Style Lock：背景色板、白平衡、肤色范围、对比度、
饱和度、纹理、字体、贴纸语言、元素密度和输出尺寸。每张图只允许在构图、姿势、
遮挡和安全留白上自适配。

首张通过 QA 后成为批次锚点。后续图片既与各自原图比较人物真实性，也与锚点比较
风格漂移。单张失败只回退该张，不得用失败结果更新批次锚点。

## 输出契约

永不覆盖原图。标准交付包含：

```text
output/
├── edited/                  通过 QA 的成品
├── originals/               原图引用或只读副本
├── reports/
│   ├── style-profile.json   样本学习结果
│   ├── batch-manifest.json  每张图的输入、计划、参数、状态和输出
│   └── qa-report.json       人物与批次检查结果
└── rejected/                失败结果；默认不作为成品交付
```

成品默认 3:5、1200×2000。裁切不得切断头发、头顶、手脚或关键道具。文字可以添加，
但必须可读、拼写正确并完全避让人物。

## 失败条件与回退

以下任一情况判定失败：人物锁定项明显变化；哭泣被改成其他表情；头发缺失；手脚、
牙齿或肢体异常；服装误改；儿童年龄感改变；肤质塑料化；文字遮挡人物或乱码；
背景边缘穿帮；批次色彩或装饰明显漂移。

失败后必须依次：降低编辑强度、缩小蒙版、删除高风险元素、退回只改背景外围、
改用传统调整、最终保留原图并报告原因。禁止用相同参数盲目重试，禁止把失败图混入
`edited/`。

## 测试计划

按测试先行执行：

1. 先为新路由、旧目录消失、输入输出契约、完整人物负向约束、六类风格、局部模式、
   3:5/1200×2000 和批次锁编写失败测试。
2. 为 Style Profile、Edit Plan、提示词编译和 manifest 编写行为测试，确认测试先因
   新能力缺失而失败。
3. 实现最小代码与文档直到测试通过。
4. 用不含真实儿童照片的合成元数据场景测试：绿色背景六图批处理、哭泣躺姿、
   仅肤色、仅裁切、Little Explorers 海报、参考风格与身份冲突。
5. 运行 Skill 校验器、仓库全部 Python 测试、脚本帮助命令、Git 差异检查和插件
   manifest 校验。
6. 更新插件源的缓存版本并重新安装；新开会话验证新 Skill 可发现、旧 Skill 不再
   出现、儿童摄影请求命中新路由。

测试和仓库中禁止加入任何真实儿童照片。

## 插件切换

仓库内容通过本机个人市场中的 `my-chatgpt-skills` 插件发布。实现完成后，插件包的
`skills/` 必须包含新目录且不含旧目录；`.codex-plugin/plugin.json` 的说明、能力和
默认提示加入儿童摄影样本学习与批量处理。使用 cachebuster 更新版本并执行插件
重装，不手工修改 marketplace 配置。由于 Skill 只在新会话加载，最终验收在新会话
进行。
