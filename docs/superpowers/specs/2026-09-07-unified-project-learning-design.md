# 统一软件项目学习 Skill 设计

## 目标

将项目学习统一为 `software-project-learning`。源码、需求、设计规格或实施计划均可作为学习证据；专业面试只是可选模式，不再通过两个高度重复的 Skill 路由。

## 名称与边界

- Skill 名称：`software-project-learning`
- 中文名称：软件项目学习教练
- 适用范围：后端或混合软件项目、现有实现、开发方案、源码、需求和架构设计。
- 不以“是否讨论优化”区分模式；两个模式都能讨论优化。
- 学习请求默认只读，不自动实施、部署或持久化学习画像。

## 证据输入

| 可用材料 | 行为 |
|---|---|
| 只有源码 | 从实际实现反推业务；推断必须标注 |
| 只有需求或设计文档 | 讲解设计；代码只能作为标注清楚的模拟实现 |
| 源码与文档都有 | 对照设计与实现，指出差异 |

项目特定结论至少需要以上一种材料。必须区分源码事实、方案要求、教学假设、模拟实现和优化建议。

## 双模式

### 项目学习模式

用于理解业务、数据、代码、可靠性机制和优化取舍。每个新模块先给 Mermaid 或关系表，再用贯穿案例和必要源码/模拟实现讲解，最后提出 1—3 个核心理解题。

用户回答后按 10 分制评判：概念正确性 4 分、因果完整性 3 分、证据与边界 2 分、表达清晰度 1 分。输出总分与等级、逐项依据、关键误区和更准确的参考回答。单次得分只描述本轮答案，不等于长期掌握度。

### 专业面试模式

复用全部项目学习能力，并加入面试官追问、标准答案、口述表达和按需 STAR 训练。先让用户回答，再评价；不得虚构用户经历或项目指标。

### 模式选择

- 用户明确需要专业面试学习、模拟面试、项目表达或 STAR 时进入专业面试模式。
- 用户明确不要面试或 STAR 时进入项目学习模式。
- 上下文明确时不重复询问。
- 无法判断时只问一次：“这次需要按专业面试场景学习和训练吗？”
- 用户可随时切换模式；保留当前模块和学习进度。

## 教学节奏

每个新模块固定先给 Mermaid 流程图或关系表。随后按“直接结论 → 贯穿案例 → 必要证据 → 核心问题”推进。同模块追问直接回答，不重复全图；用户说继续时推进下一小步，说停止时停止。

## 专业能力按需加载

- 项目建模：证据分级、业务/系统边界、责任/状态/关联模型、关键不变量和模块路线。
- 源码追踪：最短调用链、精确文件行号、方法契约、保障机制、失败路径和测试证据。
- 可靠性审查：故障矩阵、并发时间线、幂等身份、异步回执、最坏路径预算和优化取舍。

局部问题只加载当前所需的一份专业参考，并遵守深度预算：一个教学闭环、一张图或关系表、最多 5 个源码证据节点、一个最相关边界和一个理解题。专业度由可核验的证据、成立条件与风险边界体现，不通过堆叠篇幅体现。
